The database design for the tourism social network application is constructed with careful attention to modularity, scalability, and support for the system’s main features, as evidenced by its well-organized tables and relationships. The foundational structure incorporates tables such as Users, Profile, Destination, Hotel, Post, Media, Comment, Likes, Activity, and Follow. Each of these tables is designed with fields and keys tailored to optimize both storage and retrieval efficiency. For instance, the Users table manages essential authentication and identification fields such as user_id (primary key), email, hashed_password, and timestamps, ensuring both data privacy and auditability. The Profile table, linked to Users by foreign key, stores detailed personal information like full_name, avatar_url, bio, phone, and address, separating authentication from user-specific data for greater security and flexibility. 

Destinations and Hotels tables encompass tourism content, each with unique identifiers and metadata fields, such as destination_id, hotel_id, location, description, and rating, enabling users to explore, review, and interact with various tourist spots and accommodations. The Post table forms the heart of the social network component, allowing users to create and share experiences; it includes fields like post_id, user_id, destination_id, hotel_id (nullable, depending on the type of review), text_content, and creation_time. Posts are enriched by the Media table, which allows multimedia attachments for each post, with file_url, media_type, and referrer keys providing flexibility for supporting various file formats and scalable storage strategies.

Interaction on the platform is further supported by the Comment and Likes tables. Comment manages threaded discussions on posts with fields such as comment_id, post_id, user_id, text, and parent_comment_id (for replies), as well as timestamp fields to support both chronological display and moderation features. Similarly, the Likes table efficiently tracks which users have liked which posts, with unique constraints to prevent duplicate likes. To chronicle user actions and encourage community engagement, the Activity table logs events like new posts, comments, or follows, storing user_id, activity_type, ref_id, and timestamps, which can be used for dynamic feeds, notification systems, or analytics. The Follow table enables social networking by recording relationships between users, utilizing follower_id and following_id, and optimizing queries for mutual connections or suggestions.
