Figure 4.6 provides a comprehensive depiction of the processes involved when an executor—acting as a trusted member within the Distributed Key Generation (DKG) protocol—assigns an encryption key (encKey) to a user as part of social login functionality within a Web3 ecosystem. According to the detailed steps presented in Table 4.7, this process starts with the executor receiving a token from the user through Auth0, a widely-used authentication service. The executor is responsible for a sequence of verification operations, which include confirming the authenticity of the user’s token and validating any associated user information and digital signatures. If all information and signatures are confirmed to be valid, the executor proceeds to register and associate the issued encKey with the user by interacting with a smart contract. However, alternative procedural branches are defined in the flow for scenarios where validation fails, which lead to the rejection of the request and ensure the security and robustness of user onboarding.
